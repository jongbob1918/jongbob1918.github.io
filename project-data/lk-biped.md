## Problem Statement

실내 여러 층을 순찰하려면 평지 주행뿐 아니라 계단 진입·통과, 지도 전환, 다음 층에서의 주행을 연결해야 했습니다. 계단에서는 지면의 높이와 로봇의 자세가 달라지고, 목적지에서는 이동을 마친 뒤 짐벌을 움직여 주변을 관측해야 했습니다.

개발 과제는 층간 이동의 실행 순서를 관리하고, 계단의 높이 정보를 주행에 반영하며, 이동과 관측 작업을 연결하는 것이었습니다.

## System Setup

바퀴형 이족 로봇 TRON1에 로봇 소프트웨어 프레임워크인 ROS(Robot Operating System) 2 Humble과 경로 계획·주행 제어를 담당하는 Nav2(Navigation2)를 사용했습니다.

| 구성 | 역할 |
| --- | --- |
| 3차원 거리 센서(3D LiDAR, Light Detection and Ranging) | 사전 지도 작성과 현재 위치 추정 |
| 컬러·깊이 카메라(RGB-D Camera) | 근거리 형상과 깊이 관측 |
| 고도 지도(Elevation Map) | 주변 지면의 높이를 격자로 표현해 계단 주행에 활용 |
| 행동 트리(Behavior Tree) | 이동·지도 전환·관측 작업의 실행 순서 관리 |
| 짐벌 카메라 Gremsy VIO | 카메라 방향 조절과 가시광·열화상 관측 |

## Challenge 1: 층간 이동과 지도 전환 연결

### Problem

한 층 안에서 목표로 이동하는 기능만으로는 다른 층의 목적지까지 갈 수 없었습니다. 계단 진입점으로 이동한 뒤 계단을 통과하고, 도착 층의 지도와 위치 추정 상태를 준비하는 과정이 필요했습니다.

### Solution

층별 주요 지점과 이동 가능한 연결 관계를 그래프로 표현하고, 경로 탐색 알고리즘인 A*로 층간 경로를 찾는 구조를 설계했습니다. 경로 계획과 실행을 나눠, 계획된 경로를 일반 이동·계단 이동·지도 전환 작업으로 변환하도록 했습니다.

ROS 2에서는 행동 트리에 계단 진입점 이동, 진입부 거리 제어, 도착 층의 지도 전환, 위치 추정 준비 대기를 연결했습니다. 지도 전환 후 다음 이동을 시작하기 전에 새 지도를 기준으로 위치를 추정할 준비가 됐는지 확인하도록 구성했습니다.

### Remaining Problem

지도 전환이 끝나도 계단 구역 정보를 읽는 모듈에 이전 층의 정보가 남으면, 계단의 진입 방향과 상·하행 판단이 잘못될 수 있었습니다. 지도뿐 아니라 구역 정보와 현재 층 상태도 함께 갱신되는지 확인해야 했습니다.

이 문제를 추적하며 지도 전환 요청, 구역 정보 갱신, 위치 추정 준비 상태를 각각 확인하도록 검증 항목을 나눴습니다.

## Challenge 2: 계단의 높이를 반영한 주행

### Problem

계단에서는 높이 변화와 중간 참, 회전 구간을 함께 다뤄야 했습니다. 같은 수평 위치에 위층과 아래층이 겹치는 구간도 있어, 한 위치에 높이 하나만 저장하는 지도만으로 건물 전체를 표현하기는 어려웠습니다.

### Solution

층 사이의 연결 관계를 다루는 경로 계획과 로봇 주변의 지형을 다루는 고도 지도의 역할을 분리했습니다. 고도 지도를 입력받아 계단 경로를 추종하고, 전방 장애물을 확인하는 주행 제어기를 구현했습니다. 상행·하행에 따른 속도와 정렬 정책을 적용하고, 동적 장애물 감지 시 정지를 우선하도록 구성했습니다.

겹치는 층의 표현에는 사전 점군 지도를 높이별로 나누는 방식을 검토했습니다. 사전 지형과 현재 관측한 고도 지도를 결합하는 구조는 후속 설계로 정리했습니다.

### Remaining Problem

깊이 데이터가 일부 유실되면 고도 지도에서 계단 형상이 무너지고, 통과 가능한 구간을 주행 불가로 판단하는 문제가 있었습니다. 센서 원본 데이터, 좌표 변환, 지도 반영 단계 중 어디에서 오류가 시작되는지 분리해 확인할 필요가 있었습니다.

제어기 기능 구현과 별개로 실제 계단에서의 좌표 정합, 장애물 정지·재개, 반복 주행 검증을 남겨두었습니다.

## Challenge 3: 이동 후 짐벌 스캔과 작업 중단 처리

### Problem

목적지 도착 후 주변을 스캔하는 동안에도 작업 취소, 긴급 정지, 새 작업 요청을 처리해야 했습니다. 짐벌 스캔이 독립적으로 계속 실행되면 상위 작업이 끝나도 카메라가 움직일 수 있어, 작업 상태와 짐벌 동작을 함께 관리해야 했습니다.

### Solution

목적지 이동 후 짐벌 스캔을 실행하는 작업을 행동 트리에 연결했습니다. 취소·긴급 정지·새 작업 선점 시에는 스캔을 중단하고 복귀하도록 구현했습니다.

부채꼴, 나비 모양, 주변 둘러보기 패턴을 구성하고 스캔 범위를 설정 파일에서 조절하도록 했습니다. 장착 상태의 시험에서 진동과 속도 문제를 확인한 뒤, 좌우·상하 각도를 단계적으로 바꾸는 방식으로 수정하고 이동·정지 시간을 조정했습니다.

### Result

짐벌 스캔 기능의 빌드와 자동시험을 수행하고, 실제 장착 상태에서 패턴을 시험하며 동작을 조정했습니다.

## Validation & Next Steps

평지·계단·층 전환 구간의 위치 추정과 짐벌 통신·카메라 제어를 실환경에서 확인했습니다. 짐벌은 검사 시작·저장·종료 동작도 검증했습니다.

다층 이동 전체 시나리오의 반복 완주와 고도 지도 기반 계단 제어기의 실차 검증은 후속 과제로 남아 있습니다. 계단 상·하행, 정적 장애물, 사람이 경로를 가로지르는 상황을 나눠 시험 항목을 정리했습니다.
