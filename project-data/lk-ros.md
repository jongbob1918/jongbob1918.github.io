## 센서 입력부터 주행 명령까지 연결

엘케이로보틱스에서 지도 생성·위치추정과 하드웨어 통신의 ROS 2 전환을 담당했습니다. 센서 데이터를 처리하는 부분, 지도를 관리하는 부분, 주행 명령을 실행하는 부분을 나누고 ROS 2 자율주행 스택인 Nav2에 연결했습니다.

지도 저장·불러오기·삭제·목록 조회·전환 기능을 서비스로 구성했습니다. 계단 구간은 지도에 지정한 영역을 바탕으로 경로를 만들고 전용 제어기를 선택하도록 연결했습니다. 계단 주행 방식은 [이족 로봇 내비게이션](lk-biped.html)에서 설명합니다.

> 이미지 필요: 센서 입력, 지도 생성·위치추정, 지도 관리, Nav2, 로봇 통신의 연결도. ROS 1에서 ROS 2로 옮긴 범위를 표시한 그림.

## 30분 뒤부터 위치 출력이 늦어지는 문제

전환 후 처음에는 동작했지만, 장시간 실행하면 위치 출력이 늦어지고 추정 위치가 튀었습니다. 라이다 입력은 10 Hz, 관성 센서 입력은 200 Hz를 유지한 반면, FAST-LIO 위치 출력의 지연은 약 0.14초에서 0.68초로 증가했습니다.

입력 주기와 출력 지연을 비교한 뒤 기존 운영 코드와 전환 코드를 대조했습니다. ROS 1에서는 사용하지 않던 지도 발행 경로가 ROS 2에서 활성화돼 있었습니다. 스캔을 계속 누적하고 1초마다 전체 점군을 메시지로 변환해 보내면서 처리 부담이 커지는 구조였습니다.

> 이미지 필요: 같은 시간축에 라이다·관성 센서 수신 주기와 FAST-LIO 출력 지연을 표시한 그래프.

## 누적 지도 발행을 실행 경로에서 제거

누적 지도 발행을 끈 비교 시험에서는 1시간 동안 위치 발산이 관찰되지 않았습니다. 이를 바탕으로 1초 주기의 누적 점군 발행 경로를 제거하고, 원시 점군 저장은 디버깅 용도로 분리했습니다.

이 결과는 해당 시험에서 발산이 재발하지 않았다는 의미입니다. 실제 위치 오차를 기준 장비로 측정한 정확도 결과는 아니며, 센서 처리와 발행에 걸리는 시간의 세부 비중은 추가 계측이 필요합니다.

> 이미지 필요: 누적 지도 발행을 켠 시험과 끈 시험의 실행 시간별 출력 지연·추정 위치 비교.

## 전환 후 확인한 범위

7월 개발 기록에서 ROS 2 지도 생성의 실환경 검증과 평지·계단·층 전환 구간의 위치추정 점검을 확인했습니다. 다층 전체 임무와 여러 환경에서의 반복 성공률은 별도 검증이 남아 있습니다.

이번 전환에서는 빌드와 토픽 연결 이후에도 기존 운영 코드의 실행 조건을 비교해야 했습니다. 후속 검증은 장시간 실행, 카메라 동시 사용, 지도 전환처럼 처리 부하와 상태가 바뀌는 조건을 중심으로 진행해야 합니다.
